## D4-01 平台与组织审计查询

复用现有审计写入和历史记录，提供平台与组织两个显式注册的查询入口。由服务决定查询范围，仓储按授权范围读取。组织归属以事件本身的持久化字段为准，禁止按操作者或目标账号的当前成员关系推断归属。来源见 [FR-10.01–FR-10.03](prd-saas-foundation.md#fr-10-管理审计与-csv-导出)及 [AC-23](prd-saas-foundation.md#ac-23-审计与导出)。

- [x] 组织查询仅向该组织所有者开放，展示本组织允许可见的事件和字段，包括组织名称变更、所有权转移撤销与过期。通过其他组织 ID、筛选条件或翻页均无法读取其他租户或全局身份、恢复事件。
- [x] 平台查询需要有效的平台用途会话及当前平台资格，能够读取身份与平台管理事件，包括员工账号建立、平台资格变更和恢复。对带组织归属的运营事件，按照事件可见范围核验平台与组织两侧的显示，平台接口不返回成员完整联系方式。
- [x] 用 D1–D3 的实际事件核对类型、操作者、目标账号或组织、时间和结果。覆盖换绑及恢复、发送失败或超时、限额和重发、邀请链接生命周期、首位所有者改邀与取消开通、平台初始化与最后一位保护、成员治理、套餐及订阅、组织生命周期。系统事件允许无账号操作者。
- [x] 响应字段按事件类型筛选。号码变更仅返回脱敏旧号和新号，人工核验仅提供授权可查的受控引用。凭据、原始核验资料和完整联系方式均不进入审计响应。查询列表不新增审计记录。
- [x] 真实 HTTP 验证角色、跨租户、分页边界及到期前后的可见范围，验证组织不存在、非成员、归档、停用、待激活、订阅时间和角色沿用现有拒绝顺序与错误码。若历史记录无法可靠归属，组织查询须排除该记录，并记录实际影响及修正方案。

## D4-02 成员联系方式与组织审计 CSV 导出

成员 CSV 使用已有联系方式字段规则，组织审计 CSV 使用 D4-01 的授权查询范围和字段。来源见 [FR-04](prd-saas-foundation.md#fr-04-账号资料与成员联系方式)、[FR-10](prd-saas-foundation.md#fr-10-管理审计与-csv-导出)及 [AC-07](prd-saas-foundation.md#ac-07-账号资料与隐私p0)、[AC-18](prd-saas-foundation.md#ac-18-授权)、[AC-19](prd-saas-foundation.md#ac-19-租户隔离)、[AC-22](prd-saas-foundation.md#ac-22-订阅与生命周期)和 [AC-23](prd-saas-foundation.md#ac-23-审计与导出)。

- [x] 所有者和组织管理员可直接调用本组织成员联系方式导出，只包含允许字段及已验证手机号、已绑定且验证的邮箱，未绑定邮箱为空。普通成员及平台用途会话请求该导出时被拒绝。组织审计 CSV 仅对本组织所有者开放。
- [x] 两个下载入口都校验当前会话、成员关系、组织状态、订阅时段与角色。已到期保留原角色的导出能力，待激活、未生效、停用、归档均按现有规则拒绝。猜测其他组织 ID 返回约定的 `not_found`，失败使用统一 JSON 及 Trace ID 契约。
- [x] 成功响应为带下载头的 CSV。验收复读导出的列名、顺序和行数，覆盖空结果、中文、逗号、引号、换行和可能被表格程序解释为公式的字段。审计 CSV 沿用脱敏字段，禁止越过查询范围获取记录。
- [x] 每次成功导出写入一条持久化审计，记录操作者、组织、时间、种类、结果和实际数据行数，行数不含表头。审计不保存完整手机号、邮箱或文件正文。若审计写入失败，返回 `audit_unavailable`（HTTP 503），在发送下载头和文件内容之前失败。审计 CSV 以本次导出审计落库前生成的数据为计数依据。
- [x] 使用真实 HTTP 覆盖直接访问、角色降级或撤销后的请求、双组织隔离、状态码、CSV 解析和脱敏，以及审计写入故障、无文件泄露与行数一致性。

## D4-03 完整 API、接入、升级与恢复文档

让业务接入方按统一入口完成 Composer 建项、配置、显式迁移、初始化、调用、部署与故障处理。来源见 [INT-03](prd-saas-foundation.md#int-03-公开-api文档迁移与升级契约)及 [AC-24、AC-27](prd-saas-foundation.md#ac-24-命令与打包)。

- [x] 公开 API 索引覆盖 D1–D4，列出路由前缀、会话用途、角色、输入校验、HTTP 状态、封闭错误码和审计要求。包括手机号换绑、邮箱恢复及更换、平台人工恢复、员工账号授予、本人资料、组织名称、首位所有者改邀、取消开通及 CSV 下载契约。说明业务侧按实际操作显式分类查询、导出与写入，并复用租户与权限约束。
- [x] 提供安装、环境配置、迁移、版本升级与 Webman reload／restart 步骤。写明国内产品范围、+86/E.164、产品时区、短信及邮件额度及 IP 每小时最高 200 的约束，以及 Composer 安装、更新、移除与数据迁移、保留的关系。
- [x] 说明平台人工恢复的核验标准、无法核验时的拒绝行为及受控引用。分别记录初始化命令、唯一管理员离线恢复流程和日常管理 API 的适用条件、运维权限、执行步骤、审计位置和失败处理。
- [x] 写明邀请由操作者自行发送，已登录用户接受邀请仍需短信验证，平台管理员不能导出成员完整联系方式。按 PRD 列出账号注销、个人数据主体导出、个人信息留存期限及任意业务表导出的范围边界。

## D4-04 示例联调、发布制品验证与全阶段回归

用同一最小 Webman 示例演示 D1–D4，并以真实 HTTP、隔离的 MySQL 和 Redis 验证。来源见 [QA-01](prd-saas-foundation.md#qa-01-验收策略)、[AC-24–AC-27](prd-saas-foundation.md#ac-24-命令与打包)及 [总体完成条件](prd-saas-foundation.md#总体完成条件)。

- [x] 示例可按文档从干净环境启动。以发布制品为安装和升级边界，验证全新安装、显式迁移及重复迁移、初始化与首次登录，以及从 D3 升级后历史数据、审计记录、公开契约和现有会话可用。验证 Composer 生命周期无隐式迁移或删库表行为。
- [x] 运行 D4 专项及 D1–D3 回归，覆盖双租户、生命周期、受限字段、历史事件查询，以及前序敏感变更在审计写入失败时的回滚。复核响应结构、Trace ID 的透传和兜底、封闭业务错误码、未注册路由的 HTTP 404 与 `route_not_found` 及通用异常行为。
- [x] 自动化使用可控短信和邮件发送器验证无需发送、供应商接受、拒绝、超时，以及额度扣减、响应一致性和受限审计。真实 SMTP／短信联调单独记录实际状态，区分提交结果与实际送达。未执行的联调标为未验证并说明原因。
- [x] 记录实际验证的 PHP、Composer、Webman、MySQL、Redis 版本及命令、结果、未执行检查与原因。对修改的 PHP 文件执行语法检查，最后检查工作区。
